## B4. モデル取得(F-14)の確認事項(2026-11-19 追加・レビュー待ち、設計: 12)

方針(アプリ内に取得機能と専用ページを設け、複数バージョンはユーザーが選ぶ)はユーザー指示。以下は仕様の細部で、「推奨」で進めてよいか確認したい点。

| ID | 論点 | 推奨 |
|---|---|---|
| Q-32 | カタログの更新方法 | **アプリ同梱の JSON、更新はアプリのリリースで**。実行時に外部からカタログを取らない(プライバシー・安全性を優先) |
| Q-33 | 任意 URL・Civitai・Hugging Face トークン(gated モデル)の対応 | **v0.4 では対応しない**(厳選カタログのみ)。需要があれば後続で、トークンの保管方法と合わせて設計 |
| Q-34 | 初期カタログの範囲 | **SD1.5 / SDXL のベース、ControlNet 3 種 ×(SD1.5 / SDXL)、顔・手の検出モデル、Flux(schnell / dev の GGUF・テキストエンコーダ・VAE)**(12 §4.2)。LoRA・Flux 本体(safetensors)は含めない(Flux は 2026-11-19 に追加。ユーザーが schnell と dev の両方を指定) |

| Q-38 | 同時ダウンロード数・自動再開 | **同時 1 件**。アプリ終了後の自動再開はしない(`.part` は残し、手動で再開) |
| Q-39 | inpaint 専用チェックポイントのカタログ追加 | **v0.5 では見送り**(通常のチェックポイントで動く。必要になれば別設計。13 §8。2026-11-19 推奨どおり) |

## B6. ComfyUI の起動管理(F-16)の確認事項(2026-11-19 追加・推奨どおりで決定、設計: 15)

方針(画面から ComfyUI を起動・停止・再起動できるようにする)はユーザー指示。以下は仕様の細部で、「推奨」で進めてよいか確認したい点。

| ID | 論点 | 推奨 |
|---|---|---|
| Q-45 | 既定のモード | **`external`(従来どおり)。起動管理はオプトイン** |
| Q-46 | パスの決め方 | **設定で明示指定 + 起動中の ComfyUI / 08 のレイアウトからの候補自動入力**(確定はユーザー) |
| Q-47 | 再起動時に実行中のジョブがあるとき | **確認ダイアログ**。中断した実行中ジョブは失敗として記録、待機中は残す |
